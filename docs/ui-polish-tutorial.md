# UI 완성도 개선과 행동형 튜토리얼

## 적용 내용

- 보드: 현재 캐릭터 확대·이름표·발밑 링, 실제 이동 경로와 도착 칸 표시, 전경 소품 가림 제거. 100칸 및 이동 규칙 유지.
- 정보 배치: 플레이어 이름·에너지·SP 가독성 확대, 중복 턴 안내 제거, 주사위와 특수기술 정렬. 1024×600 기준으로 도감·시장·건설·결과 영역 확인.
- 로비: 9명 얼굴 선택창과 기술 이름, 키보드 포커스 순환. 도입 이야기는 명시적인 다음/건너뛰기로 진행.
- 건설: 시설 선택 후 지도 클릭 또는 방향키/Enter 배치, 기존 드래그 유지. 부적절한 지형 클릭은 재료를 소모하지 않고 선택을 유지. Esc로 선택 취소.
- 퀴즈: 해설 원리를 먼저 표시하고 정답·보상 상세를 뒤에 배치. 답변 즉시 채점 및 온라인 흐름 유지.
- 지도: 기존 지형 구성을 유지한 저용량 모형 스타일 배경과 건설 위치 정렬. [생성 방식과 프롬프트](../assets/maps/DIORAMA_SOURCE.md).
- 미니게임: 태양·패널 비교 대상을 가까운 한 줄로 제한, 풍향·터빈 정렬 비교, 공급 부족에 따른 도시 조명, 대기/사용중 기기 상태, 물→터빈→발전기→도시 흐름, 운반 물체 연결, 배터리 전달 흐름, 버스 정차 표시와 분산 하차, 창문 차단 전후 전력 비교.
- 미니게임 선택: 실제 장면 썸네일 확대, 행동 한 줄과 키 안내, 작은 화면 2열 및 키보드 스크롤. 썸네일은 새 장면으로 다시 캡처.

## 튜토리얼

로비의 **튜토리얼** 또는 `?tutorial=1`로 시작한다. 선택한 히어로와 AI 3명이 있는 별도 연습 세션이다.

1. 실제 주사위를 굴려 1칸 이동하고 재료를 획득한다. 첫 이동만 학습 순서를 위해 1로 고정된다.
2. 실제 건설 도감에서 목표 시설을 고른다.
3. 실제 퀴즈에 답하고 해설을 읽는다. 정답 여부와 관계없이 원리를 확인하고 다음으로 진행한다.
4. 스마트그리드 미니게임을 30초 진행하고 4명의 점수·보너스를 확인한다.
5. 선택한 시설에 필요한 연습 재료로 실제 건설 칸에 배치한다.

주사위 자동 진행·탐험 제한시간·퀴즈 읽기 제한은 연습에서 정지한다. 미니게임은 실제 시간/득점/AI/공동순위 규칙을 사용한다. 연습 안내는 준비 버튼을 누르기 전 자동 시작하지 않는다.

연습 종료·로비 복귀·새 모험은 세션을 초기화한다. 연습 건설, 재료, 미니게임 완료 목록, 보상은 새 모험에 이어지지 않는다. 플레이 기록이나 점수 이력 저장 기능은 추가하지 않았다.

## 검증

- CI에 `GuidedTutorialTest`, `BoardReadabilityTest`, `MiniGamesCauseEffectTest`, `MiniGamesBClarityTest` 추가.
- 실제 키 이벤트로 캐릭터 선택창 Tab 순환, 주사위, 도감 목표 선택, 퀴즈, 키보드 건설 및 정상 모험 초기화를 검증.
- 별도 실제 키 입력 시뮬레이션으로 30초 미니게임과 결과 대기를 포함한 전체 튜토리얼 완료, Esc 취소와 이전 세션 콜백 차단 확인.
- 기존 규칙·퀴즈·공동 건설·미니게임 공정성·버스 마감 애니메이션·네트워크 회귀 포함 28개 테스트 통과.
- 실제 두 프로세스 온라인 동시 진행·점수 일치와 AI 전체 30턴/19퀴즈/4인 결과 시뮬레이션 통과.
- 1280×720, 1024×600 실제 렌더 확인. Web 검사용 `TutorialBrowserSmoke.cjs`는 실제 마우스/키 입력의 단계별 화면을 남겨 육안 확인한다.

실제 교실 기기에서의 프레임 속도와 학생이 처음 접했을 때의 이해도·재미는 별도 현장 관찰이 필요하다. 이번 검증은 기능 및 화면 검증이며 학생 사용자 테스트를 대체하지 않는다.
