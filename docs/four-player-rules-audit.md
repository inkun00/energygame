# 4인 온라인 규칙 통합 검증

검증일: 2026-11-05. 엔진: Godot 4.7.2 stable, Windows, Compatibility renderer.

이 문서는 실제 네이티브 프로세스 4개를 ENet으로 연결한 **규칙·동기화 통합 테스트** 결과다. 브라우저 화면 검증, 실제 학생 사용성 평가, 학교 네트워크 검증과 구분한다. 생산 서비스에는 테스트용 명령이나 점수 조작 기능을 추가하지 않았다.

## 재현한 문제와 수정

### 건설 위치가 화면 크기에 따라 달라짐

이전에는 마을 지도 UI가 화면 픽셀 좌표를 서버에 저장했다. 다른 화면 크기의 참가자가 같은 좌표를 자신의 지도에서 다시 가까운 건설 칸으로 변환하므로 서로 다른 칸에 시설이 표시될 수 있었다.

`VillagePlacementRules.gd`에 지형·건설 칸을 모으고, 서버 저장 및 네트워크 전송 좌표를 0–1 정규화한 건설 칸 중심으로 통일했다. UI는 자기 지도 크기를 곱해 표시한다. AI의 자동 배치도 같은 규칙으로 빈 칸을 고른다.

### 동시 건설 요청의 지형·점유 검사가 서버에 없음

각 참가자 UI는 자기 화면의 빈 칸을 검사했지만, 서버는 받은 위치를 검증하지 않고 팀 재료를 소모했다. 서로 다른 시설을 같은 칸에 거의 동시에 놓거나 잘못된 지형 좌표를 요청할 때 서버에서 막지 못했다.

`GameManager.build_village_project`가 재료 및 보상 변경 **전**에 정규화된 실제 건설 칸인지, 시설에 맞는 지형인지, 이미 점유된 칸인지 확인하도록 수정했다. 실패 시 자원·에너지·시설 수가 그대로 유지된다. 다른 빈 칸으로 다시 요청하면 정상적으로 건설된다.

## 실행 명령

Godot 실행 파일 경로를 `GODOT_BIN` 환경 변수로 지정한다. 프로젝트를 처음 받았다면 먼저 `--headless --editor --path . --import`를 실행한다.

```powershell
$env:GODOT_BIN = 'C:\path\to\Godot_v4.7.2-stable_win64_console.exe'
& $env:GODOT_BIN --headless --path . --script scripts/tests/FourPlayerConstructionRulesTest.gd
node scripts/tests/run_four_player_online_test.cjs
```

Node 실행기는 `host`, `client1`, `client2`, `client3` 네 프로세스를 실행한다. 외부 방 디렉터리 대신 `127.0.0.1:18921` ENet을 사용한다. 참가자 자리는 실제 연결된 peer ID 순서로 정해지고, 모든 입력은 그 참가자 자신의 자리로 전송된다. 프로세스별 로그는 `.godot/four-player-online/*.log`에 남는다. 240초 watchdog, 프로세스 종료 코드, PASS 표시, 스크립트 오류 로그를 함께 검사한다.

## 검증 범위

| 단계 | 검사 |
| --- | --- |
| 입장 | 실제 4개 프로세스, 사람 4자리, 초기 AI 없음 |
| 준비 | 다른 사람 자리의 준비·주사위 요청 거부, 4명 모두 준비하기 전 탐험·주사위 시간 정지 |
| 보드 | 네 자리 모두 실제 주사위 요청·이동·퀴즈 응답 RPC, 중복 응답 1회만 반영, 팀 정답 수 4 |
| 미니게임 | 현재 9종 모두 동일 seed·round ID·duration, 4인 준비 장벽 및 공통 카운트다운 |
| 제한 시간 | 태양광 30초와 통학버스 60초는 실제 시간 유지, 너무 빠른 점수 및 이전 round 점수 거부 |
| 결과 | 네 명의 검증 가능한 합성 점수 400·400·300·200, 목표 행동 기록, 공동 순위 1·1·3·4와 보상 20·20·5·1 |
| 중복 방어 | 점수 재전송·결산 재호출로 중복 에너지 없음, 완료한 미니게임 타일 재방문 시 재실행 없음 |
| 복구 | 네 번째 참가자의 실제 ENet 연결 종료, 호스트 및 참가자 게임 정지, 새 transport peer ID로 원래 사람 자리·상태 복원 |
| 마켓 | 네 명의 판매·구매 요청, 중복 요청 방어, 총 재료 보존 |
| 건설 | 네 자리의 별도 시설 건설, 잘못된 지형·이전 픽셀 형식 거부, 두 다른 시설의 점유 칸 충돌 거부 |
| 엔딩 | 네 명이 건설 완료 후 같은 소유자·자원·에너지·회복도·최종 순위, 엔딩 재호출로 중복 보상 없음 |

`FourPlayerConstructionRulesTest.gd`는 지형 오류, 픽셀 좌표, NaN, 동일 칸 충돌, 거부 시 무변경, 빈 칸 재시도, AI 기본 배치의 점유 회피까지 14개 회귀 검사를 추가한다.

## 테스트 fixture와 한계

- 네 자리의 첫 주사위가 반드시 퀴즈에 도착하도록 해당 테스트 프로세스의 첫 6개 타일을 퀴즈로 바꾼다. 주사위 요청, 이동 및 퀴즈 응답 자체는 실제 네트워크 경로를 통과한다.
- 퀴즈 정답은 테스트가 데이터에서 읽는다. 학생이 문제를 풀었다는 의미가 아니다. 퀴즈 해설 읽기 및 미니게임 결과 읽기 대기만 생략한다.
- 태양광과 버스의 실제 제한 시간은 유지한다. 나머지 7종은 공통 준비·카운트다운 이후 호스트 테스트 시계만 합법적인 점수 제출 구간으로 이동한다. 모든 점수·목표 행동 기록은 규칙 검증용 합성 입력이며, 9종 게임을 사람이 조작해 얻은 점수가 아니다.
- 탐험 전체 10분을 기다리는 대신 각 자리의 행동 검증 이후 시간을 끝낸다. 건설 가능성을 확실히 검사하도록 마지막 단계에서 테스트 재료를 공급한다.
- 실제 네트워크 연결 끊김/재연결을 수행하되 재연결 시도를 약 1.4초 지연하여 정지 상태를 관찰한다. 기존 네트워크 복구 테스트가 별도로 다루는 30초 이탈 후 AI 승계는 이 시나리오에서 대체 실행하지 않는다.
- localhost ENet 성공은 인터넷 NAT, 학교 방화벽, 모바일 기기, 실제 학생 4명의 사용성 검증을 대신하지 않는다. 별도 WebRTC 및 화면 조작 검증 결과와 함께 판단해야 한다.
- 플레이 기록 저장 기능은 추가하지 않았다. 위 로그는 개발 검증 산출물이며 배포 대상 및 사용자 기록 기능이 아니다.

## 결과

- 독립 건설 규칙 회귀 테스트: **14개 통과, 종료 코드 0**.
- 4인 ENet 통합 테스트는 **2회 연속 통과**했다. 최종 실행은 호스트 313개, 참가자 163·161·161개로 총 **798개 검사**, 네 프로세스 모두 종료 코드 0이다.
- 최종 실행에는 잘못된 지형·픽셀 좌표, 이미 점유된 도시/전력 광장 칸에 대한 실제 네트워크 건설 요청의 거부와 무변경 검사도 포함된다.
- 네 프로세스 로그에 `SCRIPT ERROR`, `Parse Error`, `[FAIL]`, `ERROR:`가 없었다. `git diff --check`도 통과했다.
