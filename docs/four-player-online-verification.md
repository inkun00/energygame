# 4인 온라인 전체 흐름 검증 — 2026-11-05

이번 검증은 실제 네이티브 네트워크 프로세스 4개와 별도의 Chromium 브라우저 컨텍스트 4개로 수행한다. 실제 학생 사용성 평가나 학교 방화벽·저사양 노트북 성능 평가와 구분한다. 플레이 기록 저장 기능은 추가하지 않았다.

## 수정 내용

- **동시 입장:** 세 참가자가 같은 빈 좌석을 경쟁하던 DB 조회/삽입을 원자적인 좌석 배정으로 변경했다. 같은 참가 토큰의 재시도는 같은 자리를 유지하며 실제 만료시간도 갱신한다.
- **이전 연결 메시지:** 만료된 자리를 다른 사람이 사용할 때 이전 참가자의 WebRTC 신호가 전달되지 않도록 정리한다.
- **동시 연결 종료:** 호스트 권한 모델에 필요 없는 참가자 간 릴레이를 끄고, 같은 네트워크 poll의 연결 종료를 처리한 뒤 생존 참가자에게 상태를 알린다.
- **공동 건설:** 화면 픽셀 대신 공통 건설 칸 좌표를 전송한다. 호스트가 지형·점유를 검사한 후에만 재료를 소모한다. 요청이 거절되면 요청자의 임시 예약을 해제한다.
- **화면 일치:** 동시에 같은 시설을 다른 위치에 요청해도 호스트가 확정한 위치를 표시한다. 빠른 중복 클릭으로 빈 칸이 잠기지 않는다.
- **재접속 화면:** 이미 끝난 완주 보상·시장·도감 팝업을 정리하고, 현재 퀴즈/탐험 상태에 맞춰 재료 UI를 복원한다.
- **튜토리얼 재시작:** 이전 화면 갱신 콜백을 실제로 취소해 즉시 나가기·다시 시작 시 중복 연결 오류가 발생하지 않도록 한다.

세부 재현과 회귀 테스트는 [규칙 검증](four-player-rules-audit.md), [통신 검증](four-player-network-audit.md), [UI 검증](four-player-ui-audit.md)에 기록했다.

## 브라우저 검사 실행

Godot 4.7.2 웹 내보내기 템플릿, Node 22 이상, Playwright/Chromium이 필요하다. 저장소 루트에서 실행한다.

```powershell
node scripts/tests/export_four_player_web.cjs
node scripts/tests/run_four_player_web_test.cjs
```

필요하면 `GODOT`, `PLAYWRIGHT_MODULE_PATH`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`에 설치 경로를 지정한다. 특정 게임만 재현하려면 `FOUR_PLAYER_GAMES=grid_balance`처럼 설정한다. 기본값은 현재 구현된 9종 전체다.

- 별도 시작 씬과 `.godot/four-player-project`를 사용한다. 실제 `project.godot` 시작 씬은 변경하지 않는다. 제품 내보내기에는 `scripts/tests`, `scenes/tests`를 포함하지 않는다.
- 로컬 메모리 SQLite에서 실제 방 디렉터리 Worker를 실행한다. 브라우저끼리 실제 WebRTC 데이터 채널로 통신한다. 각 참가자는 독립 브라우저 컨텍스트를 사용한다.
- 로비 생성/참가는 실제 UI 콜백, 준비·시작·주사위·퀴즈·건설·완료는 실제 화면 버튼/키보드 입력을 사용한다.
- 미니게임 진입 종류와 마지막 재료 공급/탐험 종료만 명시적 시나리오 fixture다. 미니게임 점수는 주입하지 않으며 키보드 입력으로 얻는다. 30초 및 통학버스 60초 제한시간을 유지한다.
- 수력은 실제 물 넘침으로 30초 전에 종료할 수 있다. 자동 키 입력은 숙련 플레이를 모사하지 않으므로 목표를 달성하지 못한 게임의 0점·0보상도 정상 접수 여부를 검사한다. 학습 목표 행동과 공동 순위 보상 규칙은 별도 회귀 테스트에서 검증한다.
- 결과 네 개가 같은 것뿐 아니라 모든 실제 점수 제출이 접수됐는지 검사한다. 의도적인 재접속 구간에서 네 화면의 실제 미니게임 시계가 멈췄는지도 비교한다.
- 시장 제출, 원격 참가자의 키보드 건설, 전원 완료 후 엔딩 1회, 최종 자원·시설·에너지 일치, 방장 종료 후 안내와 로비 복귀까지 검사한다.
- `.godot/four-player-web/evidence`의 화면 캡처·상태 JSON·로그는 개발 검증 산출물이다. 게임의 사용자 기록이나 배포 자산이 아니다.

## 검증 중 구분한 테스트 도구 문제

초기 하네스의 관찰 노드가 `PROCESS_MODE_ALWAYS`였고 자식 게임까지 이를 상속했다. 이 설정은 실제 제품과 달리 재접속 대기에도 UI 시계가 진행되게 만들었다. 관찰 노드만 항상 실행하고 실제 Main은 `PROCESS_MODE_PAUSABLE`로 지정했으며, pause boolean뿐 아니라 UI 시계가 실제로 정지했는지 검사한다. 이 도구 오류 때문에 제품의 점수 검증 규칙을 완화하지 않았다.

## 배포 서버 검사

Cloudflare Worker 버전 `cd1b31e8-9d7b-4b50-b565-5262a2ead874`를 배포했다. 운영 D1에서 이 검증만을 위한 비밀번호 방을 만들고, 3명 동시 입장·2/3/4번 고유 좌석·같은 토큰의 재시도·게임 시작 후 인증된 신호 조회를 확인한 뒤 해당 임시 방만 삭제했다. 기존 사용자의 방은 조회하거나 변경하지 않았다.

## 최종 검증 결과

- 독립 Chromium 컨텍스트 4개 전체 시나리오 **PASS**, 브라우저/스크립트 오류 0. 9종 모두 네 실제 점수가 호스트에 접수됐고 전원 결과·에너지가 일치했다.
- 재접속 중 네 UI 시계가 650ms 관찰 구간에서 실제로 멈췄고, 같은 자리로 복귀한 뒤 점수가 정상 반영됐다.
- 풍력 실제 플레이 보상 `20·10·5·1`, 배터리 실제 동일 점수 4명 보상 `20·20·20·20`을 확인했다. `20·20·5·1` 경쟁 순위는 네이티브 통합 테스트의 합성 점수로 별도 확인했다.
- 수력은 자동 키 입력이 수문을 충분히 열지 못해 약 12초에 실제 넘침으로 종료했다. 정상 조기 제출로 접수됐다. 버스는 실제 60초 진행했다.
- 시장 → 원격 키보드 건설 → 전원 완료 → 네 화면의 엔딩 1회 → 동일 최종 상태 → 방장 종료 안내 → 직접 로비 복귀까지 **PASS**.
- 네이티브 4인 규칙 798개 검사, 4인 통신 35개 검사, 독립 건설 규칙 14개 검사, Worker 서비스 14개 테스트 **PASS**.
- 기존 및 신규 Godot 회귀 스크립트 **34/34 PASS**, exit 0 및 엔진 오류 없음. 튜토리얼 재시작에서 발견한 콜백 오류는 수정 후 해당 회귀를 다시 확인했다.
- 한 준비 실행에서 WebRTC 초기 연결 제한시간 초과가 발생했다. UI는 접속 실패를 알렸고 새 실행에서는 정상 연결됐다. 단일 로컬 환경의 성공을 학교 방화벽·NAT 환경까지 보장하는 결과로 해석하지 않는다. 현재 STUN 방식의 외부망 제약은 서비스 README에 명시돼 있다.
