# 화면 구성과 행동 피드백 개선

2026-11-05. 초등 4~6학년, 키보드, 4인 온라인, 노트북 웹 환경을 기준으로 적용했다.

## 미술과 화면 구성

- 초록 모형 마을을 기준으로 보드 지형·타일·공통 패널의 색과 무광 재질을 맞췄다. 일반 정보판의 테두리와 그림자를 줄이고 조작 버튼은 바닥 두께·누름·포커스로 구분한다.
- 보드 상단은 현재 플레이어만 확장한다. 대기 플레이어의 에너지·순위 글자는 20px을 유지한다. 재료 가방은 접힌 상태에서 52px이며, 상세를 펼칠 수 있다.
- 도감에는 필요한 개수만큼 부품 그림 슬롯이 있다. 실제 개인 재료가 증가하면 해당 슬롯만 채워진다. 작은 화면에서는 가방과 도감 목록을 각각 스크롤한다.
- 온라인 대기실에는 공용 마을 배경과 네 캐릭터의 발판을 배치했다.

## 행동과 결과

- 버튼 눌림은 중복 신호 연결 없이 공통으로 적용한다.
- 실제로 획득한 부품은 가방으로 이동한다. 필수 선택창이 열려 있으면 닫힌 뒤 표시하며, 다른 단계로 이동하면 이전 알림과 비행을 정리한다.
- 건설은 실제 부품 이미지 모임 → 시설 등장 → 안착의 짧은 순서로 표시한다.
- 낮·밤 시험은 건설 지도와 시설 위치·소유자를 이어 쓴다. 발전·직접 공급·충전·방전·저장량·구역 점등은 실제 전력 모형의 스냅샷에서 읽는다. 시각 효과는 모형을 진행시키지 않는다.
- 9종 미니게임 안내에는 독립된 6초 시범을 추가했다. 복제 장면의 게임 처리·입력·신호를 끄고 시각 상태만 갱신하므로 점수·준비·원본 난수를 바꾸지 않는다. 조작 연습과 준비 버튼은 그대로 연결된다.
- 버스 학생의 대기 간격·접근 경로·동작 위상을 분산했다. 분류 게임에는 기존 Kenney 환경 에셋과 공통 재질을 사용했다.

## 참고 자료

- [Mario Party Jamboree](https://www.nintendo.com/jp/switch/a7hla/sugoroku/index.html): 현재 행동자와 행동 대상의 시각적 우선순위.
- [Dorfromantik](https://www.toukana.com/dorfromantik/presskit): 마을 중심 화면과 모형의 통일감.
- [Overcooked! All You Can Eat](https://www.team17.com/games/overcooked-all-you-can-eat): 플레이어 구분과 작업 지점 피드백.
- [Dicey Dungeons](https://store.steampowered.com/app/861540/Dicey_Dungeons/): 그림 슬롯을 통한 선택 구조 전달.
- [Anthropic 공개 디자인 가이드](https://claude.com/resources/articles/improving-frontend-design-through-skills): 테마·타이포그래피·동작을 구체적으로 정하고 실제 결과를 검토하는 작업 방식. 구현은 Codex에서 수행했으며 Claude 모델을 실행한 결과는 아니다.

상용 게임의 그림이나 코드를 제품에 복사하지 않았다. 기존 에셋의 출처는 각 에셋 폴더에 유지한다. 플레이 기록 저장 기능은 추가하지 않았다.

## 검증

- 기존 38개 회귀 검사와 새 DesignPolishTest, CommercialPolishPreview, MiniGameGuidePreviewTest, VillageEnergyViewTest를 실행했다.
- 1280×720 / 1024×600 실제 렌더에서 HUD·대기실·도감·9종 안내·낮밤 지도를 확인했다.
- 새 검사로 실제 재료와 슬롯의 일치·초기화, 작은 화면 경계, 중복 버튼 신호 방지, 시범 상태 격리와 렌더 중지, 실제 마을 위치와 전력 스냅샷 불변성을 확인한다.
- 실기기 성능 수치는 기존 [렌더 성능 문서](render-performance-benchmark.md)의 조건과 한계를 따른다. 개발 PC의 렌더 확인을 학교 노트북 성능 측정으로 해석하지 않는다.

- 최종 42개 회귀 검사 통과. 초기 검수에서 발견한 축약 카드 글자 크기, 빈 플레이어 안내, 시범 막대 가림, 도감 작은 화면 넘침, 단계간 보상 알림 잔류를 수정했다.
- 실제 ENet 네 프로세스에서 9종 미니게임·퀴즈·부품·계획·건설·발전·엔딩과 재접속을 통과했다. 별도 4인 transport 검사 35개도 통과했다.
- 로컬 Web export의 TutorialBrowserSmoke로 실제 키보드/마우스를 사용해 16개 단계의 튜토리얼과 새 모험 복귀를 확인했다. 브라우저 오류가 없었다.
- 독립된 Chromium 네 세션의 실제 WebRTC로 동시 입장, 턴 권한, 30초 grid_balance 및 재접속, 네 명의 계획 확인, 원격 키보드 건설, 실제 낮밤 시험, 동일 엔딩, 호스트 이탈 복구·로비 복귀를 통과했다. 이 브라우저 실행에서 9종 전체 온라인 라운드를 반복한 것은 아니며 9종 전체는 ENet 검사와 시범·연습 검사로 확인했다.
- 검증 이미지와 로그는 `.godot/qa-guide-polish/`, `.godot/qa-web/tutorial-browser/`, `.godot/four-player-web/evidence/`에 있다. 학생 기록이 아닌 개발 검증 자료다.
