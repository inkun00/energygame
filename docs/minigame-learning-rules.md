# 미니게임 활동과 보상 규칙

이 변경은 초등 4학년이 조건을 살펴 행동하고, 실패 이유를 읽고 다시 시도할 수 있도록 활동과 득점을 연결한다. 실제 학생의 학습 효과를 입증한 연구 결과는 아니다. 목표 행동 기록은 이해도·숙달도와 구분한다.

## 공통 규칙

- 경쟁 순위는 점수로 정한다. 0점은 순위 대신 `연습`으로 표시하고 승리 횟수·에너지 보상을 주지 않는다.
- 양의 점수와 아래 목표 행동 기록이 있어야 순위별 에너지(+20/+10/+5/+1)를 받는다. 순위가 높아도 목표 행동이 부족하면 보상은 0이다.
- 보드에서는 한 번 진행한 미니게임을 목표 행동 달성 여부와 관계없이 해당 게임 세션의 완료 목록에 넣는다. 이후 같은 칸에 도착해도 다시 실행하지 않는다. 별도 미니게임 화면의 다시 플레이는 유지한다.
- 점수·목표 행동·순위는 현재 라운드와 게임 세션 안에서만 사용한다. 최고 기록, 플레이 이력, 누적 보상 등 영구 기록은 저장하지 않는다.
- 첫 모험 안내의 완료 여부도 파일에 저장하지 않는다. 공용 노트북에서 새로운 학생이 시작하면 안내가 다시 나타난다. 사용자가 직접 선택하는 마을 이미지 다운로드는 플레이 기록 저장과 별개로 유지한다.
- 성공 횟수·선택 비율은 플레이 기록이다. 학생의 이해도는 새 상황의 예측·설명과 사전·사후 평가로 따로 확인한다.
- 키보드와 터치 버튼은 동일한 조건·점수 경로를 사용한다. 중단·종료·포커스 상실 때 터치 상태를 해제한다. 터치 플레이는 가로 화면을 권장한다.
- 배터리 저장소는 이동 구간이 닿았는지도 검사해 느린 프레임에서 중앙을 건너뛰어도 저장·인출을 놓치지 않게 한다. 자원·날씨·재사용 대기 조건은 동일하게 유지한다.
- 네트워크의 스키마·라운드·시각·상한·중복 제출 검증을 유지한다. 호스트가 전체 플레이를 재현하지 않으므로 클라이언트가 보고한 행동 기록의 진실성까지 보증하지 않는다.

## 변경 전후

| 활동 | 이전 | 변경 및 목표 행동 기록 |
| --- | --- | --- |
| 태양광 | 조작하지 않아도 우연히 맞는 패널 통과가 정답 기록 | 경로 선택 후 햇빛을 향한 패널 3회 이상·패널 선택 60% 이상 성공. 장애물 점프·충돌은 개념 선택 비율에서 제외 |
| 풍력 | 제동을 계속 눌러도 일반 발전과 돌풍 보상 | 제동 중 발전 중지. 돌풍을 본 뒤 새로 누른 제동만 기록. 풍향 조절과 돌풍 대응을 각각 1회 |
| 전력망 | 무조작 자동 점수, 평균 오차와 점수 순서 불일치 | 전체 30초의 수요·공급 평균 차이가 작을수록 높은 점수(최대 3,000점). 공급을 한 번도 조절하지 않으면 0점. 변화한 수요에 맞춰 차이 6 MW 이내를 1초 유지한 행동 2회가 보상 조건 |
| 대기전력 | 대기/사용 중 기기 구분은 이미 구현 | 기존 W 비례 점수와 오차단 감점 유지. 대기 기기 2회 이상, 선택의 60% 이상 성공이 보상 조건 |
| 수력 | 빠른 연타, 높은 수문이 항상 유리한 것처럼 안내 | 연타로 개방하고 E로 닫는다. 비와 유입량이 바뀌므로 수문을 계속 열어 두는 것만으로 해결되지 않는다. 수위 70% 이상에서 물이 닿는 수문을 열고 발전한 기록과, 발전 후 수위가 실제로 줄어든 뒤 직접 닫은 기록 각각 1회가 보상 조건. 범람은 성공 기록에서 제외. 유량과 공통 낙차를 구분 |
| 분류 | 틀려도 다음 물건으로 넘어가 한 방향 반복 가능 | 정답 목록은 처음 두 물건 뒤에 숨긴다. 틀린 물건을 유지하고 이유를 제공. 고친 답은 점수 없이 연습. 처음 선택 2회 이상 성공·처음 선택의 60% 이상 성공이 보상 조건이며 재시도는 비율 분모에서 제외 |
| 배터리 | 초기 저장 1칸, 맑을 때도 공급 보상 | 빈 배터리에 먼저 저장(+20). 공통 seed의 날씨·도시 수요가 변한다. 흐린 도시로 공급(+80)한 1회만 목표 행동 기록. 맑을 때는 전기를 보유해 다음 부족 때 재시도. 공급 전력은 잠시 도시 불빛을 유지 |
| 통학 | 인당 비교가 최종 기록에 남지 않음 | 같은 길의 혼자/함께 인당 값을 최종 표시. 2명 이상을 함께 학교에 내려준 1회가 목표 행동 |
| 냉방 | 열린 창문 선택은 이미 구현, 안내 +120/실제 최대110 | 기존 조작 유지. 열린 창문 2회 이상·선택 60% 이상 성공. 냉방 사용량(게임 비교 값)을 결과에 표시. 최대110 안내로 정정 |

분류의 화석연료 설명은 지하 위치 대신 매우 긴 생성 시간을 기준으로 한다. 수력의 70%·전력망의 허용 차이 등은 교육용 게임 기준이며 실제 설비 운전 기준이 아니다. 냉방 활동은 더운 외기와 에어컨이 켜진 교실이라는 조건을 전제로 한다.

## 조작 연습과 공통 화면 스타일

수력 안내에서 P 또는 조작 연습 버튼으로 최대 12초의 선택 연습을 시작한다. 실제 이동·점프·Space 연타·E 닫기와 물→터빈→발전 애니메이션을 사용하지만 범람과 점수 제출은 하지 않는다. Esc/연습 마치기로 안내에 돌아간다. 호스트가 자동 시작하거나 재접속을 복원해도 원래 seed·수위·생산량·게이지·캐릭터 위치로 초기화하고 경쟁 라운드를 시작한다. 연습 완료 자체는 준비 완료를 뜻하지 않는다.

MiniGameVisualStyle은 9종의 하늘·바닥·구조물 색감, 조명과 무광 재질을 공통으로 정의한다. 위험 빨강·발전 표시·물과 햇빛·정답 색은 별도로 유지한다. 가져온 모델의 원본 재질을 수정하지 않고 초기 생성 시에만 재질을 조정한다. 새 후처리나 그림자맵을 추가하지 않는다. 보드의 황폐→복원 변화는 보존한다.

단독 미니게임에서는 숨겨진 보드 모달이 시작 신호·키 입력을 처리하지 않도록 비활성화한다. 비활성 보드의 3D 렌더와 마을 애니메이션도 중지한다. 따라서 수력 연습의 Space가 보이지 않는 다른 안내창을 눌러 준비 완료가 되는 것을 방지한다. 보드 게임을 시작하면 다시 활성화하며 초기 셰이더 준비 단계의 렌더는 별도로 유지한다.

## 퀴즈 전수 교정의 범위

두 JSON의 200문항을 모두 읽고 질문·정답·설명·네 보기를 검토한다. 변동 통계와 출처 없는 절약률 암기를 줄이고 조건이 명확한 생활·발전 상황 판단으로 바꾼다. 화석연료/재생에너지, 태양광/태양열, 유량/낙차, 수소의 생산 방식, 바이오매스 연소 배출 등 오개념을 교정한다. 모든 문항에 min_grade(4/5/6), difficulty(1/2/3), learning_objective를 넣고 키워드 추정보다 명시 학년을 우선한다. 학년 분류는 게임 설계상의 권장 난도이며 교사 감수·교육과정 인증·학습 효과 검증을 뜻하지 않는다.

참조 원리: [미국 에너지부 수력 설명](https://www.energy.gov/cmei/water/how-hydropower-works), [EIA 바이오매스의 환경 영향](https://www.eia.gov/energyexplained/biomass/biomass-and-the-environment.php). 특정한 게임 수치나 문항 학년을 이 기관이 승인했다는 의미는 아니다.

## 로컬 검사

Godot 4에서 가져오기 후 `godot --headless --path . --script scripts/tests/MiniGameLearningRulesTest.gd`를 실행한다. 이 검사는 9개 무행동 경로, 정상 조건 선택, 반복 제동·반복 오답·불필요 공급, 터치 상태, 0점·정상 동점·AI 완료 처리를 확인한다. 상태 배치와 합성 시간 진행을 사용하는 통제 검사이며 학생 플레이 결과가 아니다.

MiniGamesAQualityTest, MiniGamesBQualityTest, MainGameQualityTest, QualityPresentationTest로 패널 각도·난수 독립성·수력 개폐·버스 승하차·전체 시간 오차 점수·학년별 퀴즈·공동 재료·화면 배치를 확인한다. 기존 MiniGameSystemTest, MiniGameLearningFeedbackTest, MiniGameFairnessTest, StandaloneMiniGamesTest, NetworkInputValidationTest와 localhost 온라인 동기화·연결 복구 검사도 함께 실행한다.

QuizReviewedDataTest는 200문항 메타데이터·서로 다른 네 보기·학년별 전체 출제 풀·읽기 시간·중복 방지를 검사한다. HydroPracticeTest는 연습의 실제 키 조작·점수 배제·자동 시작 초기화·실제 게임 범람을 검사한다. StandaloneBrowserSmoke.cjs의 --practice와 --url 옵션으로 웹 배포본의 연습→안내→시작 흐름도 검사한다. 자동 검사는 정답의 교육적 가치나 실제 학생의 재미를 증명하지 않는다. 실제 학생·저사양 학교 노트북·학교망의 현장 검증은 별도다.
