# 공동 건설 학습 화면 검증

2026-11-05

## 진행 연결

- 퀴즈 해설을 닫은 다음 부품 카드 3개 중 하나를 고른다. 1/2/3 및 방향키·Enter로 선택하며 지급과 시간 초과 처리는 서버가 맡는다.
- 탐험 중 정한 시설 목표는 공동 계획의 추천으로 이어진다. 건설 목록은 내 추천, 친구 추천, 다른 시설, 완공 시설 순으로 정렬한다.
- 낮·밤 각 20초 동안 내 구역의 저장소만 조절한다. 날씨·바닷물 조건, 만든 전기와 필요한 전기, 충전·방전 방향, 배터리 잔량과 집의 밝기를 현재 상태에서 표시한다.
- 저장소가 없으면 저장/사용 버튼을 비활성화한다. 실제 공급 비율로 결과를 보여 주며 고정 친환경 지수를 성공 기준으로 안내하지 않는다.
- 튜토리얼은 주사위, 목표, 퀴즈·부품, 미니게임, 공동 계획, 태양광·저장소 건설, 낮·밤 전기 공급의 7단계다. 연습 기록을 저장하지 않고 새 모험은 초기 상태로 시작한다.

## 자동 검증

`LearningVillageUITest.gd`는 실제 GM 액션으로 다음을 검증한다.

- 해설과 부품 선택의 순서, 다른 학생 선택을 가리지 않는 대기 표시, 키보드 조작의 구역 소유권
- 목표와 공동 추천의 연결, 4명 준비 후 건설 전환, 빠른 전환 후 사라진 버튼에 초점을 보내지 않는 처리
- 낮 저장→밤 사용 및 최종 공급 비율, 결과 확인 대기, 1024×600·1280×720의 화면 여백

`GuidedTutorialTest.gd`는 실제 주사위·퀴즈·미니게임·배치·전기 조작을 거친다. 해설에서 실제 13.2초를 기다려도 다음 버튼을 누르기 전에는 부품 선택으로 넘어가지 않는지 확인한다. 태양광과 저장소를 각각 배치하고 낮 저장/밤 사용으로 밤 공급 100%를 검증한다.

`AdventurePresentationTest.gd`는 목표 선택이 재료를 소비하지 않으면서 공동 추천에 반영되는지, 수정된 태양광 재료와 준비·탐험 화면 전환이 맞는지 검증한다.

## 실제 렌더링

- 네이티브 OpenGL에서 부품·계획·전기 화면을 두 크기로 렌더링하여 확인했다.
- `TutorialBrowserSmoke.cjs`로 Chromium/WebGL에서 실제 마우스와 키보드만 사용해 연습 시작부터 새 모험 준비까지 진행했다. 브라우저 오류는 없었다.
- 개발 검증용 이미지: `.godot/qa-web/tutorial-browser/01-dice.png`부터 `16-fresh-adventure.png`. 04 부품 선택, 09 공동 계획, 10 건설, 13 낮 저장, 14 밤 공급, 15 결과, 16 새 모험을 확인했다.
- 이 이미지와 로그는 개발 환경의 `.godot`에만 생성하며 플레이어 기록이 아니다.

문구는 목표·조작·학습 원리·현재 결과에 필요한 내용만 남겼다. 날씨는 ‘이번 낮/밤’의 조건으로 표시하여 밤이면 항상 바람이 약해진다고 오해하지 않게 했다. 전기 버스 시설은 낮 충전 수요가 생기는 점을 시설 설명에 반영했다.
